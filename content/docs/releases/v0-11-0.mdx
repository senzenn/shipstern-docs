<Update label="2026-09-18" version="v0.11.0" tags={["Minor", "Breaking", "Fixed"]}>

Every change in this release is in `shipstern-proc-macro`, the `include_shipstern_parser!` code generator. Projects that use only built-in parsers need no code changes.

## Upgrade impact

| Who is affected | What to do |
| --- | --- |
| IDLs with a `programNode.origin` other than `"anchor"` or `"shank"` | Change the value to `"anchor"` or `"shank"`, or remove the field. |
| IDLs with byte or string fields whose length prefix is not `u32` little-endian | Expect different, now correct, decoded values. Reparse stored data from the original transactions to recover the full values. |
| `shipstern-jetstream-source` users | Take every Shipstern crate from the `v0.11.0` git tag. crates.io has `shipstern-jetstream-source` only up to 0.9.0. |
| Everyone else | Bump every `shipstern*` crate to `0.11.0`. |

## Highlights

- Generated parsers decode length-prefixed bytes and strings correctly for every prefix width and byte order.
- The macro reads IDLs with `codama-nodes` 0.13.2.

## Changed

- **Breaking:** `shipstern-proc-macro`: `codama-nodes` is pinned to `=0.13.2` (from `=0.9.1`). `codama-nodes` 0.13 models `programNode.origin` as a closed `anchor | shank` enum, so any other value is now rejected when the IDL loads, with a message naming the value. It used to be dropped silently. An absent `fixed` or `isOptional` still reads as `false`, so no account or instruction layout changes. ([#322](https://github.com/solana-rpc/shipstern/pull/322))
- `shipstern-proc-macro`: the deprecation note on the `cpi_event_discriminator` and `cpi_event_payload_offset` macro arguments no longer names a removal version. The 0.9.0 notes promised removal in 0.10, which did not happen. They still apply to IDLs that declare no CPI event envelope.

## Fixed

- `shipstern-proc-macro`: byte and string fields now use the length prefix the IDL declares. Every `sizePrefixTypeNode` was read as a `u32` little-endian prefix, so `u8`, `u16`, `u64`, `u128`, big-endian and `shortU16` prefixes read the wrong length and misaligned every later field. Decoded output changes for affected IDLs. Replaying data that was already truncated cannot recover the lost bytes; reparse from the original transaction data. No IDL bundled with Shipstern is affected. ([#325](https://github.com/solana-rpc/shipstern/pull/325))
- `shipstern-proc-macro`: counts, sizes and offsets in generated code are now unsuffixed literals (`558` instead of `558usize`), so generated parsers keep compiling when `codama-nodes` widens a count, size or offset type. Parsing behaviour does not change. ([#321](https://github.com/solana-rpc/shipstern/pull/321))

## Upgrade

```toml title="Cargo.toml"
[dependencies]
shipstern = "0.11.0"
shipstern-core = "0.11.0"
shipstern-proc-macro = "0.11.0"
# ...and every other shipstern* dependency
```

```bash
cargo update
cargo build
```

If the build fails with an error naming `programNode.origin`, fix the IDL as described in the upgrade impact table.
