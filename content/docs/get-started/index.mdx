Shipstern is a Rust framework for indexing Solana programs. An application picks a source and registers parsers and handlers:

- The source connects to a provider of Solana updates, such as a Yellowstone gRPC endpoint.
- Each parser decodes one program's accounts or instructions.
- Handlers are the application code that receives each decoded value.

Shipstern subscribes to the updates that the parsers ask for, decodes them and calls the handlers.

```rust
shipstern::Runtime::builder()
    .account(Pipeline::new(AccountParser, [Store]))         // token accounts -> Store
    .instruction(Pipeline::new(InstructionParser, [Store])) // token instructions -> Store
    .build::<YellowstoneGrpcSource>(config)                 // where data comes from, set in Shipstern.toml
    .run();
```

A pipeline joins one parser to its handlers. `Store` stands for a handler that the application defines. The [quickstart](/docs/get-started/quickstart) has the imports, configuration and complete binary for this pattern.

For a program with no built-in parser, the [`include_shipstern_parser!` macro](/docs/parsers/idl-codegen) generates one from an Anchor IDL or a Codama JSON IDL.

## Check the prerequisites

| Item | Requirement |
| --- | --- |
| Rust | 1.97.1 or newer. The mock, Solana RPC, snapshot and Jetstreamer crates depend on Agave 4.3.2 crates, which need it. |
| A data source | A Yellowstone gRPC endpoint for live data, and an `x-token` if the provider needs one. Other sources need an RPC URL, a snapshot, Fumarole access or a Triton preconf token. See [Sources](/docs/sources#compare-sources). |
| System packages | A C compiler, and on Linux `pkg-config` and the OpenSSL headers. The Kafka sink also needs CMake and the zlib headers. See [Installation](/docs/get-started/installation#system-packages). |
| Knowledge | Rust with `async` and Tokio, and the Solana account and transaction model. The [glossary](/docs/reference/glossary) defines the Solana and Yellowstone terms. |

## Use the docs with AI tools

Every page is also available as Markdown for coding agents and chat assistants.

| Need | Use |
| --- | --- |
| One page as Markdown | Add `.md` to the page URL, for example `/docs/get-started/quickstart.md`. The plain URL also returns Markdown to a request with a Markdown `Accept` header. |
| The page in a chat | The **Copy page** button above each page copies its Markdown. The menu next to it opens the page in an AI assistant. |
| An index of every page | [`/llms.txt`](/llms.txt): one line per page with its description. |
| All pages in one file | [`/llms-full.txt`](/llms-full.txt): the full text of every page. |

Give an agent `/llms.txt` first, and let it fetch the pages it needs. The full file is large.
